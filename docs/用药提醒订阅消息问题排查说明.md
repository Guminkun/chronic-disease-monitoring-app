# 用药提醒订阅消息问题排查说明

## 问题现象

用户在微信开发者工具中添加了药品并开启提醒，但没有看到微信提醒。

---

## 问题原因

### 1. 微信开发者工具的限制（主要原因）

**微信开发者工具中，订阅消息不会实际发送到用户的微信！**

这是微信官方的限制：
- 在开发者工具中，订阅消息只会在控制台显示日志
- 不会推送到用户的微信客户端
- 只有在**真实的小程序环境**中，用户才会收到实际的微信提醒

### 2. 后端定时任务未启动

订阅消息需要后端定时任务运行才能发送：
- 定时任务需要单独启动
- 默认不会随FastAPI服务自动启动

---

## 解决方案

### 方案1：使用测试脚本手动触发（推荐开发测试）

**步骤**：

1. **确保后端服务运行**
   ```bash
   cd backend
   uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
   ```

2. **运行测试脚本**
   ```bash
   cd backend
   python test_send_reminder.py
   ```

3. **查看输出结果**
   - 脚本会显示所有开启提醒的药品
   - 显示用户的订阅状态
   - 尝试发送测试消息
   - 显示发送结果

4. **检查手机微信**
   - 如果发送成功，在手机微信的"服务通知"中查看
   - 注意：开发环境可能无法实际送达

---

### 方案2：启动定时任务（生产环境）

**步骤**：

1. **启动定时任务进程**
   ```bash
   cd backend
   python -m app.tasks.medication_reminder
   ```

2. **定时任务会每分钟检查一次**
   - 检查当前时间是否匹配药品的服药时间
   - 匹配则发送订阅消息

3. **查看日志**
   - 日志会显示发送状态
   - 检查是否有错误

---

### 方案3：在真实小程序环境测试（最终验证）

**步骤**：

1. **上传小程序代码**
   - 在微信开发者工具中点击"上传"
   - 填写版本号和备注

2. **设置为体验版**
   - 在微信公众平台设置为体验版
   - 添加体验成员

3. **在手机微信中打开小程序**
   - 使用真实微信扫码进入
   - 添加药品并开启提醒

4. **等待到服药时间**
   - 会收到实际的微信服务通知

## 数据检查

### 检查药品是否开启提醒

```bash
cd backend
python -c "
from app.models import MedicationPlan
from app.database import SessionLocal
db = SessionLocal()
plans = db.query(MedicationPlan).filter(
    MedicationPlan.remind_enabled == True
).all()
print(f'开启提醒的药品: {len(plans)}个')
for p in plans:
    print(f'  - {p.name}, remind_enabled={p.remind_enabled}')
db.close()
"
```

### 检查用户订阅状态

```bash
cd backend
python -c "
from app.models import WechatSubscription
from app.database import SessionLocal
db = SessionLocal()
subs = db.query(WechatSubscription).all()
print(f'订阅记录: {len(subs)}条')
for s in subs:
    print(f'  - user_id={s.user_id}')
    print(f'    is_subscribed={s.is_subscribed}')
    print(f'    remaining={s.subscribe_count - s.used_count}')
db.close()
"
```

### 检查用户openid

```bash
cd backend
python -c "
from app.models import User
from app.database import SessionLocal
db = SessionLocal()
users = db.query(User).filter(User.wechat_openid != None).all()
print(f'有openid的用户: {len(users)}个')
for u in users:
    print(f'  - user_id={u.id}')
    print(f'    openid={u.wechat_openid}')
db.close()
"
```

## 常见错误码

| 错误码 | 说明 | 解决方案 |
|-------|------|---------|
| 0 | 发送成功 | 等待用户查看 |
| 40003 | openid无效 | 检查用户是否正确登录微信 |
| 43101 | 用户拒绝接收 | 用户拒绝订阅，引导重新订阅 |
| 47003 | 模板参数不准确 | 检查字段映射是否正确 |
| 41030 | page路径不正确 | 检查小程序页面路径 |

## 验证步骤

### 在微信开发者工具中验证订阅流程

1. **检查订阅弹窗是否正常**
   - 打开"添加用药"页面
   - 开启提醒时是否弹出授权弹窗

2. **查看控制台日志**
   - 点击"详情" -> "本地设置" -> 勾选"不校验合法域名"
   - 查看Console中的网络请求

3. **检查订阅记录**
   - 运行上面的检查脚本
   - 确认subscribe_count增加

### 在真实环境验证提醒发送

1. **上传体验版**
   - 开发者工具 -> 上传
   - 微信公众平台 -> 设置为体验版

2. **手机微信测试**
   - 扫码进入体验版
   - 添加药品并订阅
   - 等待服药时间

3. **查看服务通知**
   - 微信 -> 服务通知
   - 应该看到"服药计划提醒"

---

## 注意事项

1. **微信开发者工具限制**
   - 不会发送实际消息
   - 只能测试订阅流程

2. **订阅次数**
   - 一次订阅只能发送一次消息
   - 建议引导用户订阅多次

3. **消息发送时机**
   - 需要定时任务运行
   - 或手动触发测试

4. **真实环境测试**
   - 必须在真实小程序中测试
   - 才能看到实际效果
